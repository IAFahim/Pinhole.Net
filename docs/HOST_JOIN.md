# Host/join by invitation code — issue #45 M2

The minimal SDK: one host, one joining peer, a short code, no player accounts.
It is an additive facade over the unchanged transport — the same UDP/TCP/relay
engine, the same pinned-key tickets, the same roaming and recovery.

```csharp
// Host application:
await using var host = await PinholeSession.HostAsync(new PinholeHostSettings
{
    RendezvousEndpoints = [IPEndPoint.Parse("rendezvous.example.com:7777")],
});
Console.WriteLine(host.Code);              // e.g. KA26X1X0Z — share it with your friend
await using var connection = await host.AcceptAsync();
connection.Send("hello"u8.ToArray());

// Friend's application:
await using var connection = await PinholeSession.JoinAsync(code, new PinholeJoinSettings
{
    RendezvousEndpoints = [IPEndPoint.Parse("rendezvous.example.com:7777")],
});
if (await connection.ReceiveAsync() is { } message)
    Handle(message);
```

A runnable two-process example lives in `samples/Pinhole.CodeShare`. The
conceptual `Pinhole.HostAsync/JoinAsync` sketch maps to `PinholeSession.*`
(a static class avoids colliding with the `Pinhole` namespace).

## What a code is

- 9 Crockford-base32 characters, 45 bits of cryptographic randomness,
  generated by `RandomNumberGenerator`. Guessing a live code against the
  directory is an online attack the directory answers at its own rate.
- A capability: anyone holding the code can *join* the host. A live
  registration can only be replaced or deleted by the host's secret token —
  a joiner cannot hijack or tear down the registration.
- Registered in a `Pinhole.Rendezvous` code directory (see below), refreshed
  on a keepalive (default every 40 s; set `RefreshInterval` ≤ a third of your
  directory's TTL), and deleted on host disposal.

## Trust model — read this before shipping a game on short codes

The directory maps codes to the host's full connection string. The joiner's
handshake pins whatever key arrives, so the session is always encrypted and
authenticated **against the record the directory served**. A malicious or
compromised directory can substitute its own record and become the peer —
short codes therefore **require trusting the coordinator**, exactly as
[#45](https://github.com/IAFahim/Pinhole.Net/issues/45) requires to be
disclosed. Two authenticated paths exist alongside:

1. **Full invitation.** Share `host.FullInvitation` (the `pinhole1:` string)
   out of band — chat, voice, QR. It carries the host's pinned key; a
   substituted record fails the handshake loudly. Existing ticket flows are
   unchanged.
2. **Confirmation code.** Both sides display `host.ConfirmationCode`
   (joiners derive the same value from the invitation they dialed — 80 bits,
   `XXXX-XXXX-XXXX-XXXX`). Compare aloud; a substituted-key directory makes
   the two displays differ. This is a fingerprint check, not a PAKE.

## Running a directory

`Pinhole.Rendezvous` (the existing introducer binary) now also serves the
code directory on the same UDP socket:

```
dotnet run --project src/Pinhole.Rendezvous -c Release -- 7777 120
```

Wire additions (space-framed ASCII, same style as REG/WANT):

- `PUTC <code> <b64url-record>` → claims a free code, answers `OKCG <token>`;
  a live code answers `TokB`.
- `PUTC <code> <b64url-record> <token>` → token-holder refresh, `OKCG <token>`.
- `GETC <code>` → `OKCC <b64url-record>` or `WAITC` when absent/expired.
- `DELC <code> <token>` → deletes, `OKCD`; wrong token `TokB`.

Bounds mirror the introducer's: ≤4096 codes, records ≤1 KiB base64url,
codes 4–16 ASCII chars, TTL sweep, oldest-eviction at capacity. The
directory stores and forwards records without validating them — the
authentication always happens in the dialer's handshake, never at the
coordinator. Nothing about the existing REG/WANT/INTRO protocol changed.

Self-hosting is one command on any UDP-reachable machine; there is no
default public directory. Operator duties are the same as any UDP service:
rate-limiting at the edge if exposed, capacity planning against `MaxCodes`,
and monitoring. The SDK embeds no API tokens.

## TURN configuration, including Cloudflare

The facade rides the engine's existing relay seams:

```csharp
var options = new PinholeOptions
{
    Relays =
    [
        new TurnServerConfig(turnEndpoint, username, credential),   // RFC 5766 long-term creds
    ],
};
await using var host = await PinholeSession.HostAsync(
    new PinholeHostSettings { RendezvousEndpoints = [...], NodeOptions = options });
```

For managed TURN providers that use REST-style ephemeral credentials (coturn
`use-auth-secret`, Cloudflare Realtime TURN), issue pairs server-side with
`Pinhole.Turn.TurnRestCredentials.Issue(sharedSecret, now, lifetime, nonce)`
— username `{unix-expiry}:{nonce}`, credential `base64(HMAC-SHA1(secret, username))`.
The shared secret stays on your server; only the short-lived pair reaches
the SDK. Cloudflare's free tier (1,000 GB/month shared across Realtime
SFU+TURN, then per-GB) is a provider allowance, not a per-player bandwidth
promise: keep credentials short-lived, hand them out with the invite, and
put spending alarms on the account. An established direct connection does
not need the directory or the TURN provider to stay up — a provider outage
cannot tear down a direct route.

## Semantics and limits

- The returned connection is a plain `PinholeConnection`: unreliable
  datagrams, 1200-byte guaranteed ceiling on same-version sessions
  (1176 against 1.9.0 peers), explicit deadlines via `ConnectTimeout`,
  roaming/recovery identical to ticket dials. Disposing it closes the
  session and, for joiners, the node beneath it.
- `JoinAsync` polls the directory (`WaitTimeout`, default 30 s) and then
  dials under the engine's own `ConnectTimeout`; cancellation tokens are
  honored at both stages. An unknown or expired code is a clean
  `TimeoutException`; a lying directory that serves garbage produces a
  dial failure, never an unauthenticated session.
- One host, one joiner per code is the supported workflow (the engine's
  multi-peer behavior is unchanged; rooms/matchmaking are separate work).
